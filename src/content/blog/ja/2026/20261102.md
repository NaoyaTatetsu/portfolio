## はじめに

普段使っている ADE の [Orca](https://orca.dev) に PR を2本出して、どちらもマージされました！</br>
OSS へのコントリビュートはこれがはじめてです。何を作ったか、どう進めたかを残しておきます。

## 背景

[2026年の開発環境](/ja/blog/20261004/) にも書いたとおり、AI エージェントのセッション管理には Orca を使っていて、タスク管理は GitHub Projects に一本化しています。</br>
Orca には GitHub Projects をアプリ内で見られる機能があります。ただ、表示できるのは **Table ビューだけ** でした。GitHub Projects のビューは Table / Board / Roadmap の3種類あり、Roadmap や Board のタブを開こうとしても「未対応」で無効になっていました。

Issue を見ると、Board 対応は `help wanted` が付いていて、重複した要望が何件も閉じられているくらい求められていました。Roadmap 対応の Issue もありました。</br>
自分も毎日使う機能だったので、それなら自分で作ろう！と思ったのがきっかけです。

## 1本目：Roadmap ビューをタイムラインで表示する

https://github.com/stablyai/orca/pull/17795

Roadmap ビューを、github.com と同じようなタイムラインで表示できるようにしました。

- Issue / PR を開始日と目標日で横棒にして、月・四半期・年のグリッドに並べる
- 今日の位置に線を引く
- 棒は Status などの単一選択フィールドで色分けし、クリックすると既存の詳細ダイアログが開く
- 日付が無い項目も消さずに「No dates」として残す

![Roadmap ビュー（月表示）](https://raw.githubusercontent.com/NaoyaTatetsu/playground/main/screenshots/after-month.png)

いちばん悩んだのは、**どの日付フィールドで棒を置くか** です。GitHub の GraphQL API は、Roadmap ビューがどのフィールドを開始日・目標日に使っているかを返してくれません。</br>
そこで、「Start / Target という名前の日付フィールド」→「ビューの最初の2つの日付フィールド」→「Iteration フィールド」→「日付フィールド1つ（点で表示）」の順に推測するようにしました。Roadmap ビューでは日付フィールドが列から隠されていることも多いので、最後は各項目が実際に持っている日付まで見にいきます。

変更は約1,700行で、テストも 30件ほど追加しました。</br>
PR を出してから約5日でマージされました！メンテナーの方が main を取り込んだうえで、表示の細かい修正やテストを追加してからマージしてくれています。

## 2本目：Board ビューをカンバンで表示する

https://github.com/stablyai/orca/pull/19074

続けて、Board ビューをカンバンとして表示できるようにしました。カードをドラッグして別の列に移すと、ステータスも変わります！

- 列はビューに設定されているグループ化フィールドから作る（無ければ Status）
- 空の列も、削除済みの選択肢を指している項目の列も、github.com と同じように出す
- ドラッグでの更新は、Table ビューのステータス変更と同じ処理を使う（先に画面を更新し、失敗したら戻す）

![Board ビュー](https://raw.githubusercontent.com/NaoyaTatetsu/playground/main/screenshots/board-after.png)

ハマったのはドラッグ&ドロップです。React の `onDrop` を書いても一切反応しませんでした！</br>
調べると、Orca はファイルのドロップを処理するために、ネイティブの drop イベントを React に届く前に止めていました。アプリ内の別のカンバンと同じく、document にキャプチャで listener を登録して拾う形にしています。

こちらは PR を出してからマージまで1か月ほどかかりました。その間に他の方からもレビューをもらい、最後はメンテナーの方が修正を加えてマージしてくれました。</br>
マージのときに「Thanks for always making cool PRs」と言ってもらえたのがめちゃくちゃ嬉しかったです！

## やってみて

- **PR の説明を丁寧に書く**</br>
Orca の PR テンプレートには、ELI5（5歳児にもわかる説明）、変更前後のスクリーンショット、テスト内容、AI の利用有無を書く欄があります。テンプレートどおり埋めていくだけで、レビューする側が知りたいことがひととおり揃うようになっていました。
- **AI レビューが速い**</br>
PR を出すと、CodeRabbit などの AI レビューがすぐにコメントしてくれます。人のレビューを待つ前に細かい指摘を潰せるのはありがたかったです！
- **実装は Claude Code と**</br>
実装は Claude Code で進めて、設計の判断、レビュー、実機での動作確認は自分でやりました。PR にもそう書いています。大きめの機能でも、普段の仕事と同じやり方でコントリビュートできました。

## おわりに

自分が毎日使っているツールに、自分の欲しい機能を足せたのはかなり嬉しいです！今は Orca の中で Roadmap と Board を見ながらタスクを回しています。</br>
また欲しい機能があったら PR を出してみようと思います！
